
Experiment 1: Recording in Context Sensitive Mode and Analog Mode (Selenium IDE) 
Tools/Requirements: 
• Selenium IDE extension (Chrome/Edge) 
• Any demo site for drag-and-drop (optional) 
Procedure: 
1. Open Chrome/Edge and install the Selenium IDE extension from the browser extensions store. 
2. Click the Extensions icon and open Selenium IDE. 
3. Click 'Create a new project' and enter a project name. 
4. Click 'Add new test' and name the test case (e.g., TC_Record_Google). 
5. Click the red 'Record' button. 
6. Enter the base URL (e.g., https://www.google.com) and click 'Start Recording'. 
7. Perform actions: click the search box, type a keyword, press Enter, click a result, then go back. 
8. Stop recording and review the generated commands (open, click, type, assert). 
9. Run the test using the 'Run current test' (play) button. 
10. For analog-style actions: try recording a drag-and-drop or slider movement on a demo site and replay it. 
11. Save the project in Selenium IDE. 
Notes: 
• Selenium IDE is mainly context-sensitive (element based). True analog recording is limited. 
• For complex gestures use Selenium WebDriver code with the Actions class.

       import java.sql.*; 
       public class DatabaseCheckpointCustomCheck { 
       static final String DB_URL = "jdbc:sqlite:student.db"; 
       public static void setupDatabase() throws SQLException { 
       try (Connection conn = DriverManager.getConnection(DB_URL);  
       Statement stmt = conn.createStatement()) {  
       stmt.execute("CREATE TABLE IF NOT EXISTS students (" +"id INTEGER PRIMARY KEY, name   
TEXT, marks INTEGER)"); 
       stmt.execute("DELETE FROM students"); 
       stmt.execute("INSERT INTO students VALUES (1, 'Amit', 78)");  
       stmt.execute("INSERT INTO students VALUES (2, 'Neha', 45)");  
       stmt.execute("INSERT INTO students VALUES (3, 'Ravi', 92)"); 
} 
} 
 
public static boolean customCheckpoint(int studentId,String expectedStatus) 
throws SQLException { 
try (Connection conn = DriverManager.getConnection(DB_URL);  
PreparedStatement ps = conn.prepareStatement("SELECT marks FROM students WHERE id = ?")) { 
ps.setInt(1, studentId); 
ResultSet rs = ps.executeQuery(); 
if (!rs.next()) { 
System.out.println("FAIL: No record found for id " + studentId);  
return false; 
} 
int marks = rs.getInt("marks"); 
String actualStatus = (marks >= 50) ? "Pass" : "Fail"; 
if (actualStatus.equals(expectedStatus)) {  
System.out.println("PASS: Student " + studentId +" status = " + actualStatus + " (Custom check 
matched)"); 
return true; 
} else { 
System.out.println("FAIL: Student " + studentId + " expected " + expectedStatus +", got " + 
actualStatus);  
return false; 
} 
} 
} 
      public static void main(String[] args) throws Exception { setupDatabase(); 
customCheckpoint(1, Pass"); 
customCheckpoint(2, Fail"); 
customCheckpoint(3, Pass"); 
} }

failCount++; 
} 
}

1. User Interface (UI) Automation

• Experiment 1: Recording in Context Sensitive & Analog Mode (Selenium IDE)
	• What it does: Uses a browser extension called Selenium IDE to "record" user actions (like clicking a search box, typing text, and hitting enter) on Google. It then plays back those actions to verify the page loads correctly (assertTitle).
	• Key takeaway: Shows you the basics of "Record and Playback" browser testing. It notes that while it easily tracks element clicks (context-sensitive), complex gestures like drag-and-drop (analog mode) require advanced coding (WebDriver).

2. Verification & Validation Checkpoints

• Experiment 6: Database Checkpoint – Custom Check
	• What it does: Creates a temporary database of student records (Amit, Neha, Ravi) and their marks. The script queries the database for a specific student ID, calculates whether they passed (≥ 50 marks) or failed, and checks if that matches an expected status.
	• Key takeaway: Teaches how to build automated Database Checkpoints to verify back-end data accuracy directly from a database.

3. Data-Driven Testing (Running the same test with different inputs)

• Experiment 7(a): Dynamic Test Data Submission
	• What it does: Generates random product prices and shopping categories (electronics, clothing, etc.), calculates an automated discount, and prints the result.
• Experiment 7(b): Through Flat Files (CSV/TXT)
	• What it does: First, it writes a text file (testdata.txt) containing shopping prices and categories. It then reads that text file line-by-line to calculate discounts.
• Experiment 7(c): Through Front Grids (Web Tables)
	• What it does: Uses Java's graphical user interface framework (Swing) to create a visual spreadsheet window (UI table), loads data into it, and computes the discounts.
• Experiment 7(d): Through Excel
	• What it does: Uses a specialized library (Apache POI) to programmatically build an Excel sheet (testdata.xlsx), save it, and then read data back out of it to compute discounts.
	• Key takeaway: Experiments 7(a) through 7(d) demonstrate Data-Driven Testing, showing how to pull test inputs from four different sources: random generation, text files, UI tables, and Excel spreadsheets.

4. Batch & Suite Testing (Running multiple tests together)

• Experiment 7(e): Batch Testing – Without Parameter Passing
	• What it does: Runs a simple hardcoded "test suite" that checks basic addition and subtraction formulas sequentially.
• Experiment 7(f): Batch Testing – With Parameter Passing
	• What it does: Creates an array of multiple test equations (e.g., 2+3=5, 10-4=6, etc.). It loops through them all and evaluates them, intentionally showing a FAIL when an equation is mathematically incorrect (5-5=1).
• Experiment 8: Data Driven Batch (Batch + Multiple Data Sets)
	• What it does: Combines data-driven files with batch testing. It builds a CSV file with 4 records, runs them all sequentially as a unified test batch, and outputs a final summary report (4 Passed, 0 Failed).

5. Advanced Automation (Headless & Desktop)

• Experiment 9: Silent Mode Test Execution (Headless)
	• What it does: Runs tests silently without printing clutter to the terminal command screen. Instead, it exports all the test results (PASS/FAIL) directly into a separate text file log (silent_test_log.txt).
• Experiment 10: Test Case for Calculator in Windows Application
	• What it does: Steps out of the browser entirely to control the Windows Operating System. It opens the native Windows Calculator app (calc.exe), simulates physical keyboard presses to calculate 7 + 5 =, pauses for a second, and takes a screenshot (calculator_result.png) so a human can visually confirm the answer is 12.

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Statement;

public class JdbcDemo {

    // 1. Define Database Credentials and URL
    // (This example uses MySQL; change the URL and port according to your DB)
    private static final String URL = "jdbc:mysql://localhost:3306/your_database_name";
    private static final String USER = "root";
    private static final String PASSWORD = "your_password";

    public static void main(String[] args) {
        // SQL query to execute
        String query = "SELECT id, name, email FROM users";

        System.out.println("Connecting to database...");

        // 2. Establish connection and execute query using try-with-resources
        try (Connection connection = DriverManager.getConnection(URL, USER, PASSWORD);
             Statement statement = connection.createStatement();
             ResultSet resultSet = statement.executeQuery(query)) {

            System.out.println("Connection successful!\n");
            System.out.println("ID | Name | Email");
            System.out.println("---------------------");

            // 3. Process the results
            while (resultSet.next()) {
                int id = resultSet.getInt("id");
                String name = resultSet.getString("name");
                String email = resultSet.getString("email");

                System.out.println(id + " | " + name + " | " + email);
            }

        } catch (SQLException e) {
            System.err.println("Database error occurred!");
            e.printStackTrace();
        }
    }
}
